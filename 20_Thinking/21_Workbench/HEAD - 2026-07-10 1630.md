Short answer: almost. The URL you pasted is right for **1MCP itself**, but Perplexity Desktop doesn’t have an MCP client config file like Claude; instead you must use the **“Add custom connector”** screen you showed and put the 1MCP URL there.[1][2]

## Correct URL to use

Given your 1MCP endpoint:

- Base: `http://127.0.0.1:3050/mcp`  
- Per‑app label: `?app=perplexity` (optional but useful for 1MCP logs)[2]

On the “Add custom connector” dialog you screenshotted:

- **Name**: `1MCP`  
- **Description**: e.g. `Unified MCP server on localhost`  
- **MCP server URL**: `http://127.0.0.1:3050/mcp?app=perplexity`  

Check the risk box, click **Add**, then toggle this connector on in a chat’s sources list.

## Why the “MCP Servers” style config doesn’t apply

The block you quoted:

```json
"mcpServers": {
  "1mcp": {
    "url": "http://127.0.0.1:3050/mcp?app=cursor"
  }
}
```

is from how **Cursor / Claude / VS Code** configure MCP clients via JSON files.  Perplexity Desktop, in contrast:[2]

- Uses the **Connectors → Add custom connector** UI instead of a JSON config.[1]
- Lets you specify either a **command** for local MCPs or a **URL** for remote MCPs. Your 1MCP endpoint fits the remote‑URL pattern.[1]

So: you don’t need a `mcpServers` section anywhere for Perplexity; that concept belongs to other MCP clients.

## When you’d need a wrapper

Perplexity’s local MCP flow expects a **command to run** (e.g. `npx -y @modelcontextprotocol/server-filesystem`), and it manages stdio internally.  If Perplexity ever refused `http://127.0.0.1:3050/...` in the URL field, the fallback would be:[1]

- Run a small wrapper (like an MCP SSE client) that Perplexity starts via a command.  
- Have that wrapper talk HTTP/SSE to `http://127.0.0.1:3050/mcp?app=perplexity`.

But with the “Add custom connector” dialog you showed, you can go direct with the URL.
