As per the conversation earlier about "Where is data processed?",  may I suggest the following rewrite that can go into the Technical Solution Detail.

It can also be used in the NUH call to provide a clearer reply if this question is asked.

Native Database Environment

The primary processing environment is the native database layer, all data operations that can be expressed as database queries execute within this environment. This includes column selection, row-level filtering (for example, filtering by age threshold or demographic attribute), and aggregation operations such as average, minimum, and maximum. FITFILE supports two query interfaces for this environment: native SQL and FQL (FITFILE Query Language), a proprietary abstraction layer.

Node Compute Environment

Where database-native processing is not reasonably applicable [why applicable and not "possible"?], FITFILE routes operations to the FITFILE Node compute environment. This environment computes workloads that fall outside standard database capabilities. A transient, ephemeral copy of the relevant data is staged to the FITFILE Node's local storage for the duration of processing. Operations handled in this environment include:

- FITanon and FITtoken generation
- Privacy treatment techniques (K-anonymity, L-diversity, and related methods)
- Data profiling
- Small number suppression

Federated Deployment Model

FITFILE seeks to deploy within the Organisational perimeter, as close to the data source as possible. This positions the Node compute environment physically adjacent to the data, eliminating the need for data movement across network boundaries.

The transient copy produced during Node compute processing normally resides on the same physical infrastructure as the source database. A transient copy of the data also exists within the local database technology regardless of the processing path taken.
