## How VSO Authenticates (the part You Care about)

### The General Mechanism

VSO authenticates to Vault using a Vault auth method that accepts a Kubernetes-issued JWT (service account token). Vault's Kubernetes auth method is designed specifically for this flow. 

In VSO terms:

- VaultAuth.spec.method selects _how_ VSO logs in (you're using jwt).
- VaultAuth.spec.jwt.role selects _which Vault role_ to use.
- VaultAuth.spec.jwt.serviceAccount selects _which K8s SA token_ VSO should use to request a JWT.
- VaultAuth.spec.jwt.audiences controls the aud on the token (important when using projected service account tokens / OIDC issuer validation).
- VaultAuth.spec.mount selects which auth mount in Vault to use.

HashiCorp documents the VSO authentication objects and the "global/shared auth config" approach (VaultAuthGlobal) as well. 

### The Important Consequence

The operator pod itself is not "one identity".

Instead, VSO typically:

1. Watches VaultStaticSecret / VaultDynamicSecret CRs.
2. Looks up the referenced VaultAuth _in that namespace_ (default).
3. Requests a JWT for that namespace's configured serviceAccount.
4. Logs into Vault using the configured mount+role.
5. Reads/generates the secret from the configured Vault namespace/path.
6. Writes/updates a native Kubernetes Secret in the destination namespace.

So: auth context is driven by the CR you apply, not by the VSO controller-manager pod's own service account.

## So how is VSO Bootstrapped?

Conceptually, bootstrapping must solve a chicken-and-egg:

1. Install VSO itself (Helm chart, platform module, etc.) so the CRDs/controllers exist. 
2. Create VaultAuth/default in each namespace that will use VSO-managed secrets (so VSO knows how to login for those CRs).
3. Create the secret CRs (VaultStaticSecret / VaultDynamicSecret) that reference vaultAuthRef: default.
4. VSO reconciles and writes the nat h pods then consume).

If VaultAuth/default is missing in a namespace, you'll usually see VSO status/conditions complaining it can't authenticate, and the destination Secret won't be created/updated.
