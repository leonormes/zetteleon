For a private AKS deployment, the step that trips up a "Contributor-only" service principal is Azure RBAC role assignment. During cluster creation, AKS (or your IaC template) needs to grant built-in roles to the cluster identity (managed identity / SP) on things like the subnet (and sometimes private DNS zone). That requires the RBAC action:

- `Microsoft.Authorization/roleAssignments/write` ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal?utm_source=chatgpt.com "Assign Azure roles using the Azure portal - Azure RBAC"))

## What Role Your Deployment SP Needs

To be allowed to do `Microsoft.Authorization/roleAssignments/write`, the deployment identity must have one of these built-in roles at the _scope where it's assigning roles_:

- User Access Administrator _(common minimum)_ ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal?utm_source=chatgpt.com "Assign Azure roles using the Azure portal - Azure RBAC"))
- Role Based Access Control Administrator _(also works)_ ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal?utm_source=chatgpt.com "Assign Azure roles using the Azure portal - Azure RBAC"))
- Owner _(also works, but broader than necessary)_ ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal-subscription-admin?utm_source=chatgpt.com "Assign a user as an administrator of an Azure subscription ..."))

So the practical answer is:

> Keep your SP as Contributor for resource creation, and additionally grant it User Access Administrator at the specific scope(s) where AKS needs to create role assignments. ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal?utm_source=chatgpt.com "Assign Azure roles using the Azure portal - Azure RBAC"))

## Which Role AKS is Trying to Assign (the One it "creates")

Most commonly (especially with custom VNet/subnet), AKS tries to ensure the cluster identity has:

- Network Contributor on the subnet (so it can manage LB/IPs/VMSS NICs, etc.). This is why failures often mention not being able to create a role assignment on the subnet and lacking `roleAssignments/write`. ([Microsoft Learn](https://learn.microsoft.com/en-us/answers/questions/2129362/private-aks-provisioning-this-subnet-does-not-have?utm_source=chatgpt.com "Private AKS - Provisioning -This subnet does not have the ..."))

For private clusters involving private DNS, you may also see role assignment needs around:

- Private DNS Zone Contributor on the private DNS zone (not always; depends whether you use a custom private DNS zone / how you configure private DNS). ([Azure Docs](https://docs.azure.cn/en-us/aks/private-clusters?utm_source=chatgpt.com "Create a private Azure Kubernetes Service (AKS) cluster"))

## Where to Scope "User Access Administrator"

Grant User Access Administrator to the _deployment_ SP at whichever scopes AKS (or your templates) will assign roles:

- Subnet scope (very common)
- Private DNS zone scope (if you're using custom private DNS / pre-created zone)

This is usually preferable to giving it User Access Administrator at the entire subscription.

## Why Contributor Isn't Enough

Contributor can create resources, but can't assign RBAC roles. Assigning roles needs `Microsoft.Authorization/roleAssignments/write`, which is explicitly called out as a prerequisite and is included in roles like User Access Administrator / RBAC Administrator / Owner. ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/role-based-access-control/role-assignments-portal?utm_source=chatgpt.com "Assign Azure roles using the Azure portal - Azure RBAC"))

## Summary: Service Principal Permissions for Private AKS Deployment

### The Core Problem

When deploying a private AKS cluster with `--private-dns-zone system` (the default), AKS automatically:

1. Creates a Private DNS Zone (`privatelink.<region>.azmk8s.io`) in the node resource group
2. Creates an A record for the API server
3. Assigns the `Private DNS Zone Contributor` role to the cluster's managed identity on that DNS zone

This automatic role assignment requires the deploying identity (your SP) to have `Microsoft.Authorization/roleAssignments/write` permission.

---

### What Your Service Principal Needs

|Role|Scope|Purpose|
|---|---|---|
|Contributor|Subscription|Create resources (VMs, load balancers, etc.)—you have this ✓|
|User Access Administrator OR Role Based Access Control Administrator|Subscription (or target RG)|Allows `Microsoft.Authorization/roleAssignments/write`—this is what you're missing|

---

### The Specific Permission

The permission your SP needs is:

```
Microsoft.Authorization/roleAssignments/write
```

This is included in:

- User Access Administrator (broader—includes `Microsoft.Authorization/*`)
- Role Based Access Control Administrator (narrower—only role assignment write/delete + read)
- Owner (broadest—includes everything)

---

### The Role AKS Needs to Assign

During private cluster creation, AKS assigns:

|Role|To|On|
|---|---|---|
|Private DNS Zone Contributor|Cluster's managed identity|The auto-created Private DNS Zone|
|Network Contributor|Cluster's managed identity|VNet/Subnet (if BYO VNet)|

### Your Options

Option A: Add Role Based Access Control Administrator to the SP

```bash
# This gives just enough permission to assign roles
az role assignment create \
  --assignee <SP_APP_ID> \
  --role "Role Based Access Control Administrator" \
  --scope /subscriptions/<SUBSCRIPTION_ID>
```

Option B: Add User Access Administrator (slightly broader)

```bash
az role assignment create \
  --assignee <SP_APP_ID> \
  --role "User Access Administrator" \
  --scope /subscriptions/<SUBSCRIPTION_ID>
```

Option C: Create a Custom Role (least privilege)

```json
{
  "Name": "AKS Deployer Custom",
  "IsCustom": true,
  "Description": "Contributor + role assignment for AKS private clusters",
  "Actions": [
    "*/read",
    "*/write",
    "*/delete",
    "Microsoft.Authorization/roleAssignments/write",
    "Microsoft.Authorization/roleAssignments/delete"
  ],
  "NotActions": [
    "Microsoft.Authorization/elevateAccess/Action"
  ],
  "AssignableScopes": ["/subscriptions/<SUBSCRIPTION_ID>"]
}
```
