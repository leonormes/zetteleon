## AGENTS.md

This file provides context about this Obsidian vault for AI agents.

### Vault Overview

This vault functions as a high-fidelity 'thinking engine' and personal knowledge management system, deeply specialised at the intersection of complex technical infrastructure engineering (Kubernetes, Helm, Cloud Architecture) and cognitive optimisation protocols for managing ADHD.

It is explicitly designed as a living laboratory for AI-human collaboration, focusing on transforming rapid capture and forensic analysis into synthesised, permanent knowledge, particularly concerning the 'FitFile' ecosystem, Rust development, and CUE data architecture.

### Organization

The vault employs a rigorous, numbered, lifecycle-based folder structure to manage information flow from raw ingestion to archival, enforcing a clear process for knowledge maturation.

Key organisational components include:

- Ingestion/Temporal: `00_Inbox` for initial capture and `01_journals/Dailies` for temporal logging.
- Action/System: `10_Actions/11_Projects` for active work, and `10_System` housing agent prompts, templates (like PRODOS), and metadata (`fileClasses`).
- Synthesis/Knowledge Base: `20_Thinking/21_Workbench` for transient work (marked by `HEAD -` prefixes) and `30_Library` for permanent knowledge, structured via atomic Zettelkasten nodes (`100_zettelkasten`), project context (`200_projects`), Maps of Content (`MoC`), and authoritative procedural manuals (`SoT`).
- Archival: `99_Archive` for processed items, often marked by AI assistance (`Processed_By_Agent`).

Linking is dense and structural, relying heavily on `MoC` files as topical hubs and `SoT` files as procedural guides, reinforcing a systemic approach to knowledge retrieval.

### User Preferences

The user mandates a highly technical, protocol-driven interaction style, demanding responses that are precise and 'defluffed' (minimal conversational filler). There is a strong preference for structural intelligence, meaning outputs should align with established methodologies found in `SoT` files and adhere to defined architectural patterns.

Consistency is required regarding agent roles; the system expects the AI to adopt specific personas (e.g., 'Architectural Guardian') when appropriate, and to recognise transient work via the `HEAD -` prefix in the workbench. The user also values 'Future Self Briefs' and momentum-building task sequences.
