# 7\.8 Best Practices for Security Groups

## Key Points

Apply the least privilege principle when creating security group rules for ENIs.
Regularly review and audit security group rules to prevent excessive access.
Use distinct security groups for different types of traffic (e.g., worker node to pod communication).

Card 1: Security Groups Applied to ENIs

Title: Security Groups are Applied to ENIs

Content: In cloud environments like AWS, security groups are applied to Elastic Network Interfaces (ENIs), which connect resources (e.g., EC2 instances) to the virtual network.

Card 2: ENIs and Multiple Security Groups

Title: ENIs Can Have Multiple Security Groups

Content: An ENI can have multiple security groups assigned, allowing for complex combinations of traffic control rules for different types of network traffic.

Tags: Cloud, Networking, Security, ENI, Multiple Security Groups

References: Network security, traffic control.

---

Card 3: Flexibility of ENIs and Security Groups

Title: Flexibility of ENIs in AWS

Content: Since security groups are tied to ENIs, the ENI and its associated security group rules can persist independently of resources like EC2 instances. This adds flexibility to the network management.

Tags: Cloud, Networking, Security, ENI, Flexibility

References: Elasticity in AWS, persistent network interfaces.

Card 4: ENIs as Points of Connection

Title: ENIs are the Point of Network Connection

Content: ENIs serve as the network interface connecting resources (like EC2 instances) to the virtual network. Security groups are applied at the ENI level to control traffic.

Tags: Cloud, Networking, Security, ENI, Virtual Network

References: EC2 network connections, traffic control through ENIs.
