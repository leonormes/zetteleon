# API object 

Okay, the Kubernetes API is quite extensive and also extensible, meaning the full list of available object Kinds can vary between clusters, especially with CustomResourceDefinitions (CRDs) installed. 

However, I can provide a list of the most common and core API objects, grouped by their general area of concern. Think of these as the standard "class library" that Kubernetes offers out of the box. Common Core Kubernetes API Objects: Here's a breakdown of well-known objects: 1. Workloads: These objects are used to manage and run your containerised applications.  \* Pod (pods, po): The smallest and simplest Kubernetes object. A Pod represents a single instance of a running process in your cluster, and can contain one or more containers (like Docker containers).  \* ReplicaSet (replicasets, rs): Ensures that a specified number of Pod replicas are running at any given time.  \* Deployment (deployments, deploy): Provides declarative updates for Pods and ReplicaSets. You describe a desired state, and the Deployment controller changes the actual state to the desired state at a controlled rate.  \* StatefulSet (statefulsets, sts): Manages the deployment and scaling of a set of Pods, and provides guarantees about the ordering and uniqueness of these Pods. Used for stateful applications.  \* DaemonSet (daemonsets, ds): Ensures that all (or some) Nodes run a copy of a Pod. Useful for cluster-level agents like log collectors or monitoring agents.  \* Job (jobs): Creates one or more Pods and ensures that a specified number of them successfully terminate. Used for batch tasks.  \* CronJob (cronjobs, cj): Manages time-based Jobs, similar to cron entries. 2. Service Discovery & Load Balancing: These objects help you expose your applications as network services.  \* Service (services, svc): An abstract way to expose an application running on a set of Pods as a network service. Provides a stable IP address and DNS name.  \* EndpointSlice (endpointslice, eps): Provides a scalable and extensible way to track network endpoints for Services. Generally managed by Kubernetes itself. (Endpoints (ep) is the older, less scalable version).  \* Ingress (ingresses, ing): Manages external access to services in a cluster, typically HTTP. An Ingress can provide load balancing, SSL termination, and name-based virtual hosting.  \* IngressClass (ingressclasses): Defines a type of Ingress controller. 3. Configuration & Storage: These objects manage configuration data and persistent storage for your applications.  \* ConfigMap (configmaps, cm): Used to store non-confidential configuration data in key-value pairs. Pods can consume ConfigMaps as environment variables, command-line arguments, or as configuration files in a volume.  \* Secret (secrets): Used to store sensitive information, such as passwords, OAuth tokens, and SSH keys.  \* PersistentVolume (persistentvolumes, pv): A piece of storage in the cluster that has been provisioned by an administrator or dynamically provisioned using Storage Classes. It is a resource in the cluster, just like a Node is a cluster resource.  \* PersistentVolumeClaim (persistentvolumeclaims, pvc): A request for storage by a user. It is similar to a Pod. Pods consume node resources and PVCs consume PV resources.  \* StorageClass (storageclasses, sc): Provides a way for administrators to describe the "classes" of storage they offer. Different classes might map to quality-of-service levels, or to backup policies, or to arbitrary policies determined by the cluster administrators. 4. Metadata & Namespacing: Objects for organising and describing other objects.  \* Namespace (namespaces, ns): Provides a scope for names. Names of resources need to be unique within a namespace, but not across namespaces. They are a way to divide cluster resources between multiple users.  \* Label (though not an object itself, labels are key-value pairs attached to objects, used for organisation and selection)  \* Annotation (key-value pairs attached to objects for non-identifying metadata)  \* OwnerReference (part of an object's metadata, defining ownership for garbage collection)  \* Finalizer (part of an object's metadata, allowing controllers to complete operations before an object is deleted) 5. Cluster Resources: These represent the cluster itself and its components.  \* Node (nodes, no): Represents a worker machine in Kubernetes, formerly known as a minion.  \* ComponentStatus (componentstatuses, cs): Holds status information for cluster components like the scheduler or controller-manager. (Less commonly interacted with directly by users).  \* Event (events, ev): Provides insights into what is happening inside a cluster, such as decisions made by the scheduler, or why some Pods were evicted from a Node. 6. Authorisation & Authentication: Objects related to security and access control.  \* ServiceAccount (serviceaccounts, sa): Provides an identity for processes that run in a Pod.  \* Role (roles): A namespaced set of permissions.  \* ClusterRole (clusterroles): A non-namespaced (cluster-wide) set of permissions.  \* RoleBinding (rolebindings): Grants the permissions defined in a Role to a user or set of users within a namespace.  \* ClusterRoleBinding (clusterrolebindings): Grants the permissions defined in a ClusterRole to a user or set of users across the entire cluster. 7. Policy: Objects for defining policies within the cluster.  \* NetworkPolicy (networkpolicies, netpol): Defines how groups of Pods are allowed to communicate with each other and other network endpoints.  \* PodSecurityPolicy (podsecuritypolicies, psp): (Deprecated and removed in Kubernetes v1.25. Replaced by Pod Security Admission or external admission controllers). Defines security constraints that Pods must run with.  \* PodDisruptionBudget (poddisruptionbudgets, pdb): Specifies the minimum number or percentage of replicas of a collection of Pods that must be up at any given time.  \* LimitRange (limitranges, limits): Provides constraints that can:    \* Enforce minimum and maximum compute resources usage per Pod or Container in a namespace.    \* Enforce minimum and maximum storage request per PersistentVolumeClaim in a namespace.    \* Enforce a ratio between request and limit for a resource in a namespace.    \* Set default request/limit for compute resources in a namespace and automatically inject them to Containers at runtime.  \* ResourceQuota (resourcequotas, quota): Provides constraints that limit aggregate resource consumption per namespace. 8. Extensions: Objects for extending Kubernetes functionality.  \* CustomResourceDefinition (customresourcedefinitions, crd, crds): Allows you to define your own object Kinds to extend the Kubernetes API.  \* APIService (apiservices): Used to register an API server for API aggregation, allowing you to extend Kubernetes with custom APIs served by your own server.  \* MutatingWebhookConfiguration (mutatingwebhookconfigurations): Defines how mutating admission webhooks are called.  \* ValidatingWebhookConfiguration (validatingwebhookconfigurations): Defines how validating admission webhooks are called. How to Get the Definitive List for Your Cluster This list is a good overview of the built-in types, but for the most accurate and complete list of all resource types available in your specific Kubernetes cluster (including any CRDs that have been added), you should use the kubectl command-line tool: kubectl api-resources  This command will output a list of all available API resources, their short names, the API group they belong to, whether they are namespaced, and their Kind. You can get more details (like supported verbs) with: kubectl api-resources -o wide  And to understand the structure (fields, types) of any specific resource, you can use: kubectl explain <resource.kind> # For example: kubectl explain pod kubectl explain deployment.spec.strategy  This should give you a comprehensive way to explore all "classes" available in your Kubernetes environment.
