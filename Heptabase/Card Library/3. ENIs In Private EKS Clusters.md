## 3\. **ENIs In Private EKS Clusters**

In private EKS clusters, ENIs are crucial for managing network traffic between the **EKS worker nodes**, **Kubernetes services**, and other AWS resources within the VPC. Here's how ENIs fit in:

### 3\.1 **ENI And the VPC CNI Plugin**

In a private EKS cluster, the **AWS VPC CNI plugin** manages the creation of ENIs for worker nodes. The plugin assigns **IP addresses** from the VPC subnet to Kubernetes **Pods**, using ENIs. This enables pods to have direct VPC-level networking, meaning they can communicate with other AWS services and resources in the same VPC natively.

- **ENI-per-Pod Allocation**: Each worker node uses ENIs to allocate IP addresses for the pods running on the node. The ENI associated with the pod provides direct network access to other resources in the VPC.

- **Primary and Secondary IP Addresses**: Each ENI has a primary IP address, but the VPC CNI plugin allows secondary IP addresses to be assigned to the same ENI. These secondary IPs are assigned to pods, allowing the worker node to host multiple pods with unique IP addresses.

### 3\.2 **Private Networking for EKS**

In a **private EKS cluster**, the **Kubernetes control plane endpoint** is private and accessible only within the VPC. ENIs play a key role in connecting the worker nodes to the control plane over the private VPC network.

- **Worker Node to Control Plane Communication**: Worker nodes need ENIs to communicate with the control plane through **private endpoints**. When deploying EKS in private subnets, the ENIs on the worker nodes handle all intra-VPC traffic, allowing worker nodes to communicate securely with the control plane and other Kubernetes services.

- **ENIs and Security Groups**: Each ENI attached to the worker node uses security groups to control traffic. This allows you to define which pods or instances can access specific resources or services within the VPC, following the security best practices defined for your private EKS deployment.

### 3\.3 **ENIs And Load Balancing in EKS**

In private EKS, ENIs are also involved in **load balancing** Kubernetes services, especially for services using **AWS Load Balancer Controllers**. ENIs enable:

- **Internal Load Balancing**: When you create an internal load balancer (such as an ALB or NLB), ENIs are used to route traffic to the worker nodes hosting the pods.

- **Service Traffic**: ENIs allow pods to route traffic to other services within the VPC or externally if necessary (e.g., to other VPCs through VPC Peering or Transit Gateway).
