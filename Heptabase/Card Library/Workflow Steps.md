## Workflow Steps

1. Create a Project Hub Note: For each Terraform or GitOps project/learning area, create a new note using the "Project Hub" template. Name it clearly (e.g., "Terraform AWS VPC Setup," "GitOps Kubernetes Deployment").
2. Purpose & Principles: Briefly define _why_ you're tackling this. This is your anchor. Examples:

   - Motivation: "Learn Terraform to automate AWS infrastructure."
   - Principles: "Keep it simple, focus on reusable modules."

3. Outcome Visioning: What does "done" look like? Be specific, but flexible. Examples:

   - Desired Outcome: "Automated creation of an AWS VPC with Terraform."
   - Success Criteria: "VPC created via Terraform, tested with basic connectivity."

4. Brainstorming: Dump everything here. Don't filter. Examples:

   - Ideas: "Use Terraform modules for VPC, subnets, and security groups."
   - Resources: "[Terraform AWS Provider Documentation](https://registry.terraform.io/providers/hashicorp/aws/latest/docs)," "[AWS VPC Documentation](https://docs.aws.amazon.com/vpc/)"
   - Questions: "How to handle Terraform state management?", "What's the best practice for tagging resources?"

5. Organising: After brainstorming, identify key areas or sub-topics. Create separate notes for each and link them back to the Project Hub. This breaks down complexity. Examples:

   - Key Areas:
      - \[\[Terraform State Management\]\]
      - \[\[AWS VPC Resource Tagging\]\]

6. Identifying Next Actions: Define the _very next physical action_. This is crucial for momentum. Examples:

   - Next Action: `- [] Read the Terraform documentation on state management.`
   - Due Date: `2025-05-22`

7. Daily/Regular Review:

   - Open your Project Hub notes.
   - Review "Next Actions."
   - Do the next action.
   - Update the Project Hub as you learn.
   - Create new notes for new sub-topics.
   - Define the _next_ next action.
