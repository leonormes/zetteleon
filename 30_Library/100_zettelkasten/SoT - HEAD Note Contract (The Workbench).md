> Canonical status: this note is the authoritative spec for what may live in `20_Thinking/21_Workbench/`. It is the workbench counterpart to [[SoT - ProdOS Frontmatter Contract (Note Type Schemas)]] (note-level schema) and [[SoT - Typed Edge Vocabulary (Knowledge Graph Relations)]] (edges). Where this note and a prompt disagree, this note wins. [[AGENTS]] §0, §6 and [[Reference - File Structure]] §D link here.

## Minimum Viable Understanding (MVU)

A HEAD note is an open question the human owns—one unresolved thing that requires _his_ judgement, parked somewhere he will see it. It is not a capture, not a summary, not a document, and not a finished piece of analysis. The workbench is a queue of live thinking, and its usefulness is a direct function of how short it is: a workbench holding 44 items where 22 are web clippings is not a queue, it is a second inbox that nobody triages.

This contract exists because the workbench silently became that. The Obsidian Web Clipper was writing captures straight into `20_Thinking/`, which meant the folder's signal—_these are the things I am currently thinking about_—was diluted to the point of uselessness. Capture now goes to `00_Inbox/`. The workbench holds questions.

The corollary matters as much as the rule: an unresolved tension recorded inside a canonical SoT is invisible. It sits in a note the reader consults for answers, in a section they skim. Tensions belong in the queue they will actually be worked from, with the SoT retaining a one-line pointer so its reader still knows the note is not settled.

## 1. The Four Compliance Tests

A note in `20_Thinking/21_Workbench/` MUST pass all four. Each is binary—if you have to argue for a pass, it is a fail.

| # | Test | Question | Fail → |
|:--|:-----|:---------|:-------|
| 1 | Ownership | Does this contain at least one unresolved question that is _mine_ to resolve—requiring my judgement, values, or context, not just a lookup? | `00_Inbox/` |
| 2 | Origin | Was this generated by thinking—mine, or a dialogue I took part in—rather than captured from an external source? | `00_Inbox/` |
| 3 | Convergence | Is the question still open? A note whose question has been answered is finished thinking, not active thinking. | [[Prompt - ProdOS Chronos Synthesizer]] → SoT, then `99_Archive/` |
| 4 | Actionability | Does it state what would settle it—the evidence, experiment, decision, or conversation that closes the thread? | Human fixes in place (adds `## What Would Settle It`); agents set `closing_condition: false` and report ([[AGENTS]] §6.1) |

### 1.1 The Origin Test is Mechanical

Any of these frontmatter keys is an automatic Origin failure, no judgement required:

```text
source:  source_url:  url:  author:  published:  captured:  clipped:
```

These are the Web Clipper's signature. A note carrying them is a capture. It may be _interesting_, it may later _provoke_ a HEAD note—but it is not itself thinking, and it goes to `00_Inbox/` for normal ingest via [[Prompt - Vault Ingest Router]].

A capture that genuinely provoked a question does not get to stay by association. Route the capture to the inbox, and write a _separate_ HEAD note stating the question it provoked, linking back to it in `sources:`. The question is the thinking; the article is the stimulus.

### 1.2 What the Workbench is Not

| Not a HEAD note | Where it goes |
|:---|:---|
| Web article, video summary, clipped page | `00_Inbox/` |
| Finished engineering analysis / RCA / design writeup | `30_Library/200_Projects/` |
| Checklist, runbook, per-site procedure | `30_Library/100_zettelkasten/` as a `Protocol -` note |
| Vault audit output, migration report | `90_Audits/` |
| Meeting notes, raw transcript | `00_Inbox/` |
| Settled or testable claim | `30_Library/100_zettelkasten/` as an atomic `claim` note (`status: seed` Tier 1 or `stable`), then compiled into an `SoT -` argument thread via [[Prompt - ProdOS Chronos Synthesizer]] |
| A task | Todoist. The vault does not hold actions. |

## 2. Schema (Progressive Elaboration)

A HEAD note is a `QuestionNote` that lives in the workbench. It inherits the `QuestionNote` schema from [[SoT - ProdOS Frontmatter Contract (Note Type Schemas)]] §3.4 rather than inventing a parallel one, using **progressive elaboration** so capture stays zero-friction:

1. **At Capture (`10_System/templates/HEAD_note template.md`):** Only the minimal fields required for K-Plex (`type: question`, `tags`), `Thinking.base` (`status: open`), `AGENTS.md` §6.1 (`own_words: true`), and `validate_note_frontmatter.py` (`conformant: false`, `non_conformance_reason: quick capture — awaiting clarification`, `created`, `modified`) are written. No empty `[]` fields, no `AoL` modal, and no forced H2 sections.
2. **During Triage / Work:** Add `AoL`, `tension`, `candidate_answers`, `related_claims`, `sources`, `closing_condition`, and flip `conformant: true` as the thought matures:

```yaml
---
title: "HEAD - <the question, ending in ?>"
type: question
own_words: true                # set on human-drafted HEAD notes (10_System/templates/HEAD_note template.md); omitted on agent-harvested stubs
tension: "<the belief, observation, or competing [[Claim]] that generates this question>"
candidate_answers: []          # optional [[wikilinks]] to candidate claims; may be empty
related_claims: []             # [[wikilinks]] to claims/SoTs this bears on
sources: []                    # [[wikilinks]] to notes or captures this tension was harvested from
tags: [state/thinking, prodos/head]
conformant: true
status: open                   # open | thinking | resolved
AoL: Personal                  # Personal | Work | System — area of life, drives Thinking.base views
closing_condition: true        # false = Test 4 not yet satisfied; surfaces in the "No exit condition" view
created: <ISO8601>
modified: <ISO8601>
---
```

### 2.1 Title Format

`HEAD - <question>?`—the title MUST be a question ending in `?`.

This is a forcing function, not decoration. "HEAD - The Trap of the Architect" tells you a topic; "HEAD - Am I using architecture work to avoid physical initiation?" tells you what is actually unresolved, and lets you notice when it stops being unresolved. A topic can sit open forever without anybody feeling the debt. A question cannot.

Legacy notes are not auto-renamed. Renaming rewrites every backlink and is a human decision; non-question titles on pre-2026-08-03 notes are flagged by [[Protocol - Workbench Compliance Sweep]], never changed by an agent.

### 2.2 Body Structure

At capture, the body is **free-form**—write whatever sparked the thought without filling out a form. When a thread becomes load-bearing during triage or elaboration, structure it around:

- **The Question** (the open thing, stated plainly)
- **What Would Settle It** (the evidence, experiment, decision, or conversation that closes the thread)
- **What I Currently Think** (your own words; if any wording came from an LLM, remove `own_words: true`)

### 2.3 Why `AoL`, `closing_condition`, and K-Plex Relational Fields Exist

These properties drive `02_bases/Thinking.base` and K-Plex's Idea Compass without requiring agents to touch protected body prose ([[AGENTS]] §6.1):

- **`AoL` (`Personal` | `Work` | `System`):** Splits the queue in `02_bases/Thinking.base` by context so a personal question does not sit next to a compiler question. The value is what you can act on _in the mood you are currently in_.
- **`closing_condition` (`true` | `false`):** Mirrors Test 4 into frontmatter so `02_bases/Thinking.base`'s **No exit condition** view can surface open threads that lack a `## What Would Settle It` condition. Set `closing_condition: false` honestly.
- **K-Plex Idea Compass & Facets mapping:** `type: question` places HEAD notes in K-Plex's `prodos-types` **Questions** ring, while `status` (`open` | `thinking` | `resolved`) drives `02_bases/Thinking.base` (**Workbench Board**, **In progress**, **Ready for Chronos**). Relational frontmatter fields map directly onto the Idea Compass:
  - `sources` → **North (`parents`)**: originating notes or captures that sparked the question.
  - `tension` → **East (`rightFriends`)**: competing claims or friction points generating the question.
  - `candidate_answers` → **South (`children`)**: candidate resolutions.
  - `related_claims` → **West (`leftFriends`)**: lateral supporting context.

## 3. Lifecycle

```text
capture ──→ 00_Inbox ──→ [Vault Ingest Router] ──→ 30_Library/100_zettelkasten
                                │
                                ↓ (provokes a question)
   tension on claim in SoT ──→ 20_Thinking/21_Workbench (HEAD) ──→ [Chronos] ──→ atomic claim (seed/Tier 1) ──→ SoT argument thread + Next Test
                                │                                                                                    │
                                └────────────────────────────── still open ←─────────────────────────────────────────┘
```

A HEAD note leaves the active queue in three ways:

1. **Resolved:** Once Leon fills in `## What I Currently Think`, [[Prompt - ProdOS Chronos Synthesizer]] extracts the human-authored proposition into an atomic `claim` note (`status: seed` Tier 1 while still maturing, or `stable` once evidenced/falsifiable), compiles/transcludes it (`![[...]]` with `[depends_on::]` / `[synthesizes::]`) into the target `SoT -` argument thread in `30_Library/100_zettelkasten/`, proposes dropping the `> Open threads:` pointer (§4), and sets the HEAD note to `status: resolved` (or moves it to `99_Archive/`).
2. **Archived / Retired via `status: resolved` (In-Place or `99_Archive/`):** Older thinking notes that are no longer active can be set to `status: resolved` (in place or moved to `99_Archive/`) rather than deleted. `status: resolved` notes are excluded from active `Thinking.base` views while remaining accessible in **Ready for Chronos** (and **Workbench Board**'s `resolved` column) for history.
3. **Abandoned:** The question stopped mattering. State that explicitly in the note, set `status: resolved`, and optionally move to `99_Archive/`. An abandoned question is a legitimate outcome; a silently rotting one is not.

There is no fourth exit. A note that has been `status: open` for more than 90 days is flagged as stale in `02_bases/Thinking.base` and surfaced by [[Protocol - Workbench Compliance Sweep]] (§5).

### 3.1 Tombstones

Decided 2026-07-27, after an audit found ~24 atomic notes citing four merged-and-removed HEAD notes as `upstream`, every one a dangling wikilink. Absorbed from [[SoT - Evolutionary Note System]] on 2026-10-17.

- **Rule:** A HEAD note is not fully retired until its exact title still resolves. Archive it to `99_Archive/`, or, if its content is genuinely gone, create a tombstone at the HEAD's exact original title in `99_Archive/`. Deleting a HEAD with no trace is a violation.
- **Tombstone shape:** `type: tombstone`, `prodos.kind: head`, `prodos.lifecycle: archived`, then one line stating what the HEAD was, which surviving SoT or atomic notes absorbed it, and which notes cited it as `upstream`.
- **Why the filename and not an alias:** Citing notes hold the exact string in an `upstream:` field or prose wikilink. Only a same-titled file resolves them without editing each citing note.
- **Who:** Leon, or [[Protocol - Workbench Compliance Sweep]] once Leon approves its routing table. [[Prompt - ProdOS Chronos Synthesizer]] only lists the proposed tombstone, per [[AGENTS]] §6.1.

### 3.2 Future Automation Candidates (NeuroStack)

Conserved from the superseded [[SoT - Evolutionary Note System]]; these remain design candidates rather than live rules:

- **Stale-note detection:** A note surfacing in search where it does not belong is treated as a prediction error and a signal to reconsolidate or deprecate it.
- **Excitability decay:** Recently active notes rank higher in retrieval while unused ones fade via exponential decay.
- **Tiered retrieval:** Retrieve triples first, then summaries, then full content, to conserve context tokens.
- **Session briefs:** Automatically rebuild active mental context after interruptions.

## 4. Tensions Live in the Queue, Pointers Live in the Canon

A canonical note (`SoT`, `Claim`, `MoC`, project) MUST NOT carry a `## Tensions & Gaps`, `## Open Questions`, or equivalent prose section for live open questions. Those sections are where open problems go to be forgotten—the reader of an SoT is looking for the answer and skims past the caveats.

Instead, the canonical note carries a single pointer line directly beneath its `MVU`/opening section:

```markdown
> Open threads: [[HEAD - <First open question>?]] · [[HEAD - <Second open question>?]]
```

This preserves the one thing the inline section was genuinely good at—warning a reader at the point of reading that the note is not settled—while moving the thinking itself into `20_Thinking/21_Workbench/` where it will be worked. When challenging a specific assumption or premise inside an `SoT` argument thread, open the `HEAD` tension against the underlying `claim` (via `tension:` / `related_claims:`) so the rest of the SoT argument remains intact.

**Scope limit (Closability Test):** This applies to _unresolved, closable_ tensions. A note may still record a _documented trade-off_ or _scope boundary_ in prose (e.g. "the compiler deliberately does not parse visible inline fields")—that is settled knowledge about a limitation, not an open question. If evidence, an experiment, or a decision can close it, it belongs in a HEAD note; if it is a permanent property of the design, it stays in the SoT as prose.

## 5. Enforcement & Tooling Boundary

- [[Protocol - Workbench Compliance Sweep]]—_Runs the four compliance tests over `20_Thinking/21_Workbench/`, backfills missing `QuestionNote` frontmatter, and produces a routing table for Leon's approval (emits `implements` → this contract, rendered South as `implemented_by` in K-Plex)._
- [[Prompt - Tension Harvester]]—_Harvests closable `## Tensions` sections from canonical notes into clustered HEAD notes and proposes §4 `> Open threads:` pointers (emits `implements` → this contract)._
- [[Prompt - ProdOS Chronos Synthesizer]]—_Converts answered HEAD notes (`## What I Currently Think` populated by Leon) into canonical `SoT -` notes and a verifiable Next Test (emits `implements` → this contract)._

Agent write scope in `20_Thinking/` is strictly bounded by [[AGENTS]] §6.1: an agent MAY create a new HEAD note when asked and MAY move a non-compliant or resolved note via `git mv` after Leon approves the routing table, but MUST NOT edit the body prose or `own_words` field of any existing HEAD note. On existing `HEAD` / Type B drafts (`own_words: true`), agents act as **sparring partners**—proposing claim splits, rival hypotheses, falsifiers, or `candidate_answers` in chat or frontmatter—without overwriting Leon's own-words prose.

## 6. Why Questions and Not Topics

The workbench is working memory, and working memory is expensive. Everything in it costs attention every time you look at the folder. A topic-shaped note ("The Trap of the Architect") has no closing condition, so it never leaves—it accumulates, and the folder degrades into a graveyard that is psychologically easier to ignore than to read. That is the failure mode this contract is built against, and it is the same failure mode the Web Clipper produced by a different route: anything that can enter the workbench without a defined exit will fill it.

A question has an exit by construction. That is the whole design.
