Purpose: To harmonize the structural organization of PARA with the execution workflow of GTD. This protocol is the single source of truth for defining work and "done."

---

## 1. The Definition: Projects vs. Containers

To resolve the conflict between "Folder" and "Outcome," we use the following hierarchy:

### The Hierarchy

1. PARA Project (The Container): A folder/tag representing a _Major Commitment_ or _Area of Focus_ (e.g., "Website Redesign", "Health"). It contains material, notes, and _multiple_ Outcomes.
2. GTD Project (The Outcome): A specific, finishable goal that requires >1 action step (e.g., "Homepage Mockup Approved"). This is the primary definition of "Project".
3. Task (The Atomic Action): A single, physical action step (e.g., "Email Sarah re: colors").

### The Rules

- Rule of Residence: Every GTD Project must live inside a PARA Container (Area or Project Folder).
- Rule of Activity: A PARA Container is only "Active" if it contains at least one active GTD Project. Otherwise, it is a Resource or Archive.
- Naming Convention: GTD Projects must be named as Completed Outcomes (Past Tense).
    - _Bad:_ "Website Work" (This is a Container name)
    - _Good:_ "Homepage Mockup Approved" (This is a Project)

---

## 2. The Workflow: 5-Stage Checklist

Use this checklist to process inputs into the system.

### ☐ Phase 1: Capture (The Inbox)

- [ ] Capture 100% of open loops to a trusted inbox (Digital/Physical).
- [ ] Do not process while capturing.

### ☐ Phase 2: Clarify (The Decision)

For each item, ask: _Is it actionable?_

- [ ] No: Trash it, Reference it (PARA Resource), or Incubate it (Someday/Maybe).
- [ ] Yes (< 2 mins): Do it immediately.
- [ ] Yes (> 2 mins):
    - One Step? Create a Task.
    - Multiple Steps? Create a GTD Project (Outcome).

### ☐ Phase 3: Organize (The Sorting)

- [ ] Projects: Move the Project Outcome to the appropriate PARA Container.
- [ ] Tasks: Assign a context (e.g., `@computer`) and a parent Project.
- [ ] Blockers: Add `@waiting_for` if dependent on others.

### ☐ Phase 4: Reflect (The Review)

- [ ] Weekly: Scan all PARA Containers. Ensure every active Container has at least one defined GTD Project.
- [ ] Weekly: Ensure every GTD Project has at least one Atomic Next Action.

### ☐ Phase 5: Engage (The Action)

- [ ] Execute tasks based on Context + Energy + Priority.

---

## 3. The Exit: Definition of Done (DoD)

A Project or Task is not "Done" until it meets the Exit Criteria.

### Project DoD (Outcome Level)

1. Outcome-Based Title: Name is in past tense (e.g., "Tax Return Submitted").
2. Deliverable Verified: The physical artifact exists (Document, Code, Receipt).
3. Loops Closed: No remaining "Waiting For" dependencies.

### Task DoD (Atomic Level)

1. Binary State: It is either 100% done or not started. No "90% done".
2. MVP Mindset: "What is the smallest version of this that counts?" (e.g., Draft sent vs. Perfect email).
3. Tidy Exit: Clean up the workspace (digital/physical) after completion for the next session.
