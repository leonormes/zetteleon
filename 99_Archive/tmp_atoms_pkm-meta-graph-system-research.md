### Atom 001: The Collector's Fallacy Conflates Gathering with Assimilation

- Kind: definition
- Statement: The Collector's Fallacy is the cognitive bias in which the brain confuses the mechanical act of gathering information into a centralised location with the actual cognitive assimilation of that knowledge.
- Scope & Conditions: Applies specifically to modern digital PKM environments where capture friction has been removed; the saved artefact is stripped of the relational context in which it was discovered and sits dormant.
- Evidence: "This bias occurs when the brain confuses the mechanical act of gathering information into a centralized location with the actual cognitive assimilation of that knowledge."
- Implications:
    - A growing note count is not evidence of learning.
    - The remedy is forcing active processing (e.g. testing new capture against existing questions) rather than measuring capture volume.

### Atom 002: Sweller's Three Cognitive Load Types Must Be Balanced in Any Knowledge System

- Kind: definition
- Statement: John Sweller's Cognitive Load Theory identifies three distinct types of cognitive load a learning or knowledge-management environment must balance: intrinsic load (the inherent difficulty of the subject matter), extraneous load (load generated by how information is presented, e.g. poor interfaces or unnecessary admin tasks), and germane load (effort dedicated to constructing and automating cognitive schemas in long-term memory).
- Scope & Conditions: A system that focuses on storage rather than sensemaking maximises extraneous load and minimises germane load.
- Evidence: "Sweller identifies three types of cognitive load that must be balanced in any learning or knowledge management environment."
- Implications:
    - Elaborate folder structures and over-formalisation are extraneous load, not intrinsic complexity.
    - A PKM system should be evaluated by whether it maximises germane load (forcing active relation of new to existing concepts), not by how much it stores.

### Atom 003: Sensemaking Proceeds Through Generation, Data-Coverage, and Representational-Shift Loops

- Kind: mechanism
- Statement: Daniel Russell's sensemaking model describes three learning loops: the Generation Loop (searching for an initial representation or schema), the Data Coverage Loop (encoding collected data into that schema), and the Representational Shift Loop (discovering "residue"—ill-fitting or missing data—that forces categories to be split, merged, or discarded).
- Scope & Conditions: Applies to any process of actively organising ill-structured or multidisciplinary data into a representation, not passive storage.
- Evidence: "As data is encoded, the user inevitably discovers 'residue'—ill-fitting or missing data that does not belong in the current schema. This residue forces a bottom-up, data-driven representational shift."
- Implications:
    - The friction of a concept not fitting an existing category is valuable signal, not a failure of the schema.
    - A meta-graph project should expect and design for constant representational shift rather than a single fixed taxonomy.

### Atom 004: Feynman's Twelve Favorite Problems Acts as a Continuous Curiosity Filter

- Kind: heuristic
- Statement: The Twelve Favorite Problems framework requires articulating roughly a dozen open-ended, personally significant questions spanning different life domains, then continuously testing new incoming information against each dormant problem to see if a connection can be made.
- Scope & Conditions: The problems are not tasks to be completed but continuous attractors for information; most new information will not correlate with any of them.
- Evidence: "As the individual consumes new information, they systematically test the new data against each of the twelve dormant problems to see if a connection can be made. Most of the time, there is no correlation. However, when a hit occurs, it bridges seemingly unrelated domains."

### Atom 005: Conceptual Blending Integrates Two Domains Through Four Mental Spaces

- Kind: mechanism
- Statement: Fauconnier and Turner's Conceptual Blending Theory models new-meaning creation through a conceptual integration network of four mental spaces: Input Space 1 and Input Space 2 (each holding one domain's specific elements and organising frame), a Generic Space (the abstract structure shared by both inputs), and a Blended Space (where selectively projected elements from the inputs combine into emergent structure not present in either input alone).
- Scope & Conditions: Applies to genuine cross-disciplinary synthesis, not simple analogy-spotting; the Blended Space's structure must be new, not merely a union of the two inputs.
- Evidence: "The blended space develops its own emergent structure and meaning not found in any of the original spaces."
- Implications:
    - A structural gap between two unconnected note-clusters can be deliberately treated as Input Space 1 and Input Space 2 to force generation of a Generic Space and a new synthesis note.
    - This gives a concrete procedure for turning "these two things seem unrelated" into an authored bridge note.

### Atom 006: Conceptual Integration Networks Have Four Typologies Distinguished by Shared Framing

- Kind: distinction
- Statement: Fauconnier and Turner classify conceptual integration networks into four types: Simplex (one input supplies an organising frame, the other supplies values to fill it), Mirror (both inputs share the same organising frame, enabling direct comparison), Single-scope (inputs have different frames but only one is projected into the blend), and Double-scope (inputs have different frames and the blend incorporates parts of each, yielding a genuinely novel emergent structure).
- Scope & Conditions: Double-scope blending is the only type that produces a truly novel, interdisciplinary emergent structure rather than a comparison or a framework application.
- Evidence: "Double-scope: Both input spaces have different organizing frames, and the blended space incorporates parts of each, yielding a highly novel, emergent structure."
- Implications:
    - When authoring a bridge note between two domains, naming which of the four types is being attempted clarifies whether the goal is comparison (Mirror), framework transfer (Single-scope), or genuine new synthesis (Double-scope).

### Atom 007: Ranganathan's PMEST Facets Decompose a Subject Without Forcing a Single Parent Category

### Atom 008: Betweenness Centrality Identifies Interdisciplinary Bridge Concepts

### Atom 009: A Faceted PKM Schema Should Separate Domain (Visible Subject) from Theme (Cross-Cutting Mechanism)

- Kind: distinction
- Statement: In a faceted PKM design, "domain" should record the visible subject area a note belongs to (e.g. archery, Kubernetes, literature), while "theme" should record a mechanism or question that cuts across domains (e.g. feedback, resilience, deliberate practice); a single note may carry several domains and up to a few themes simultaneously.
- Scope & Conditions: Themes should only be promoted from candidate terms to formal theme nodes once they repeatedly link at least three distinct domains; themes that merely duplicate a domain name should be retired or merged.

### Atom 011: Equating Semantic Similarity with Knowledge Is a PKM Anti-Pattern

- Kind: failure_mode
- Statement: Treating embedding-based semantic similarity between notes as if it were an authored, meaningful relationship is an anti-pattern; similarity search can retrieve candidate connections, but only an authored predicate plus rationale creates a durable assertion about how two ideas actually relate.
- Scope & Conditions: Applies specifically to systems that use vector/semantic search (e.g. RAG-style retrieval) as an input to graph construction.
- Evidence: "Equating semantic similarity with knowledge: Similarity retrieves candidates; an authored predicate plus rationale creates a durable assertion."
- Implications:
    - Semantic search should nominate candidate links for human (or LLM-with-review) confirmation, never write a link directly on the basis of similarity alone.
    - An LLM agent proposing edges should be required to state confidence and rationale, and a human/reviewer must confirm before the edge is committed.

### Atom 013: Network Graph Views Can Induce Apophenia Through Software-Drawn Connections
