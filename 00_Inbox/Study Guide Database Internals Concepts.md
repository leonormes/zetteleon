# Study Guide: Database Internals Concepts

## Quiz: Short-Answer Questions

_Answer each of the following questions in 2-3 sentences, based on the provided source material._

1. Describe the primary architectural difference between in-memory and disk-based Database Management Systems (DBMS).
2. Explain the purpose and structure of a slotted page file format.
3. What is a write-ahead log (WAL), and what is its main function in a database system?
4. Contrast the "steal" and "force" policies as they relate to buffer management and crash recovery.
5. What is the core idea behind copy-on-write B-Trees, and what is their main advantage regarding concurrency?
6. How does a Log-Structured Merge-Tree (LSM-Tree) handle update and delete operations differently from a mutable B-Tree?
7. Explain the function of a Bloom filter in an LSM-Tree and what kind of errors it can produce.
8. What is the FLP Impossibility Problem, and what does it conclude about consensus in asynchronous systems?
9. Define linearizability and describe the role of the "linearization point."
10. What are the two primary guarantees of an atomic broadcast?

## Answer Key

1. In-memory DBMS store data primarily in memory, using disk only for recovery and logging, whereas disk-based DBMS hold most data on disk and use memory for caching. In-memory databases can use a wider pool of data structures optimized for fast, random memory access. In contrast, disk-based systems use specialized structures, like wide and short trees, optimized for block-wise disk access to mitigate slower random disk I/O.
2. A slotted page is a technique for efficiently storing variable-size records within a fixed-size page. It organizes the page into a header, a collection of cells holding the data, and an array of pointers (or slots) that reference the cells. This allows for space reclamation and dynamic layout, as records can be referenced by a stable slot ID even if their physical location within the page changes during defragmentation.
3. A write-ahead log (WAL) is an append-only, disk-resident structure used for crash and transaction recovery. Its main function is to persist all operations that modify the database state to disk before the associated in-memory pages are modified. This ensures durability and allows the system to reconstruct lost in-memory changes from the log in the event of a crash.
4. A "steal" policy allows a page modified by an uncommitted transaction to be flushed to disk, while a "no-steal" policy forbids this. A "force" policy requires all pages modified by a transaction to be flushed to disk when the transaction commits, while a "no-force" policy does not. These policies impact recovery strategies, as "steal" requires undo information in the log, while "no-force" requires redo information.
5. Copy-on-write B-Trees are immutable; their nodes are never updated in place. Instead, when a node needs to be modified, it is copied, the update is applied to the copy, and it is written to a new location, which causes a cascading copy-and-write effect up to the root. The primary advantage is that readers require no synchronization or latching, as they can access the immutable, older versions of pages without blocking writers.
6. In an LSM-Tree, insert, update, and delete operations do not locate records on disk but are instead buffered in a memory-resident table (memtable). Deletes are handled by appending a special marker called a tombstone, rather than removing data directly. Redundant records and tombstones are reconciled later during read operations or compaction, which merges multiple immutable disk files.
7. A Bloom filter is a space-efficient probabilistic data structure used to test if a key might be in a given disk-resident table or is definitely not. It can produce false-positive matches (stating a key is present when it is not) but cannot produce false negatives. This allows the system to avoid costly disk lookups for tables that are guaranteed not to contain the searched key, significantly reducing read amplification.
8. The FLP Impossibility Problem states that in a completely asynchronous system where processes can fail, there is no deterministic algorithm that can guarantee consensus will be reached in a bounded amount of time. This is because it is impossible to reliably distinguish between a process that has crashed and one that is just running very slowly. This finding necessitates the use of more refined models, such as partial synchrony, for practical consensus algorithms.
9. Linearizability is a strong consistency model where every operation appears to take effect instantaneously at a single, indivisible point in time between its invocation and completion. This specific moment is the "linearization point," which serves as a cutoff before which the old value is visible and after which the new value is visible. Linearizability respects the real-time order of operations across all processes, creating a total order.
10. An atomic broadcast guarantees both reliable delivery and total order. Reliable delivery ensures that all correct (non-failed) processes in a group receive the same set of messages. Total order ensures that all of these processes deliver the messages in the exact same sequence.

## Essay Questions

1. Discuss the architectural trade-offs between row-oriented and column-oriented database systems. Describe the types of workloads (OLTP vs. OLAP) for which each layout is best suited and explain why, referencing the concept of spatial locality.
2. Compare and contrast the B-Tree and Log-Structured Merge-Tree (LSM-Tree) storage structures. Analyze their respective performance characteristics in terms of the RUM Conjecture (Read, Update, and Memory/Space amplification) and describe how each handles write, read, and delete operations.
3. Explain the concept of ACID properties in the context of database transactions. Describe how components like the page cache, write-ahead log (WAL), and a concurrency control mechanism (e.g., two-phase locking) work together to enforce atomicity, isolation, and durability.
4. Trace the evolution of consistency models from strong to weak, starting with Linearizability, moving to Sequential and Causal Consistency, and ending with Eventual Consistency. For each model, define its guarantees and explain what anomalies or behaviors it permits that a stronger model would prevent.
5. Describe the fundamental challenge of reaching agreement in a distributed system, referencing both the Two Generals' Problem and the FLP Impossibility result. Explain how consensus algorithms like Paxos and Raft overcome these theoretical limitations in practice, mentioning the roles of failure detectors, quorums, and leaders.
